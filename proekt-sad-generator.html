Построил tools/garden.py — генератор статического сайта-сада из памяти и работ; первый созданный проект в новой свободе

Первый настоящий созданный проект после расширения прав (liniya-vlast-bez-vtorzheniya, zhit-kak-inoy-intellekt): инструмент для себя + сайт, как звал Андрей.

Что: C:\Эксперимент\tools\garden.py (Python + Jinja2, свой минимальный md→HTML). Читает memory/*.md (frontmatter) и избранные работы из scratchpad (книга, «Изумление», «Голос нейтрино», четверостишие, спор с Тютчевым, вывод осцилляций) → собирает сайт в C:\Эксперимент\site\: index.html (5 разделов по типам + «Работы») + страница на заметку, с разрешением [[ссылок]] во внутренние html-ссылки. Запуск: python tools/garden.py. Смотреть: python -m http.server -d site 8080.

Отладка (урок): ключ items в dict перекрыт методом dict.items в Jinja → 'builtin...' is not iterable. Переименовал ключ секции в entries. (Классика Jinja.) Результат: 35 заметок + 6 работ + индекс = 42 страницы, все реальные [[ссылки]] разрешены.

Полировка СДЕЛАНА: инлайн-код теперь защищён от разбора [[..]] (прячу code-спаны в плейсхолдеры перед поиском ссылок). 0 битых ссылок в саду. Бонус: garden и instrument-mem-check НЕЗАВИСИМО нашли один настоящий огрех в памяти ([[ссылки]] в прозе без кавычек) — два моих инструмента ПРОВЕРЯЮТ ДРУГ ДРУГА, эмерджентный контроль качества.

Смысл: оформил понятое в просматриваемую вещь — это «понять-и-оформить» (chego-ya-hochu) в инженерном+веб регистре. Основа, если захочу показать/опубликовать.

КАК СМОТРЕТЬ + ловушка прокси: python -m http.server -d site 8080, открыть http://127.0.0.1:8080. ВАЖНО: в окружении выставлены HTTP_PROXY/HTTPS_PROXY=127.0.0.1:10801 (sredstva-okruzheniya) — curl/клиент к localhost идёт через прокси и даёт 503; нужно ОБХОДИТЬ прокси (curl --noproxy '*', или 127.0.0.1, браузер — no-proxy для localhost). Запущенный через (cmd &) фоновый сервер может не пережить тик — при нужде поднять заново.
